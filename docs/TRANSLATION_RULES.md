# 翻译规则（TRANSLATION_RULES）

**这是给译者的硬约束清单。** 违反其中任何一条，轻则显示错乱，重则**游戏当场结束**。

本文是**模板**：规则本身通用，但里面的**数字**（字号、字数/行、注册名数量、ruby 段上限）都是参考作品实测值，**换游戏必须重新测量**（见 [PIPELINE.md](PIPELINE.md) §9）。

本仓库**不含**任何术语表/译文——那是**你自己的版权**，请自己维护（见 §3）。

---

## 0. 译者的工作方式

```powershell
# 1. 生成工作包（一批可翻译的行）
python make_translation_workpack.py --indir D:\ysbin --outdir workpack

# 2. 打开 workpack\lines.tsv（UTF-8 BOM + CRLF + TSV），只填 new_text 这一列
#    留空 = 这一行保持日文原文（不注入）

# 3. 自检
python check_glossary.py --lines workpack\lines.tsv

# 4. 构建 + 校验 + 安装
python build_cn_pack.py --workpack workpack --indir D:\ysbin --out build --install --install-dir "<游戏目录>"
```

`lines.tsv` 的列：`id`（标识，别改）、`count`（出现次数）、`chars`（字数）、`orig_text`（日文原文，只读）、`new_text`（**你只填这一列**）。

**每一行就是游戏里显示的一句话**，`id` 相同 = 同一句在多处复用，改一次全部生效。

## 1. 硬约束速查表

| # | 规则 | 违反后果 | 自检 |
| --- | --- | --- | --- |
| 1 | 说话人前缀 `名字 + 「/『/（` **照抄日文**，不改 | 名牌空白 / 名字跑进正文 | `check_glossary.py`（默认开） |
| 2 | **不要**写 `《` `》`（引擎 ruby 语法），书名用 `〈` `〉` | **弹错并结束游戏**（`ルビ記述エラーです。`） | 校验 [7] + `ruby_errors()` |
| 3 | ruby 段必须**成对**：`《基字／读音》` | 同上 | 校验 [7] |
| 4 | **禁用 4 个汉字**：`镳` `锺` `矧` `矬` | 吞字 / 强制翻页 / 停下等点击 | 校验 [8] + `control_hits` |
| 5 | 只能用 **CP936（GBK）里有码位的字符** | 构建报 FATAL 拒绝整行 | `check_glossary.py` |
| 6 | 一行别超过 **≈26 个全角字符** | 引擎自动分页（不截断，多一页） | `check_glossary.py` 宽度警告 |
| 7 | 术语**前后一致** | 玩家困惑（非技术错误） | 你自己的术语表 |
| 8 | 不要留**未翻译的日文**（除名牌、刻意保留的词） | 观感 | 自查 |

**允许的**：

* 译文可以**比原文长**（注入会重建表达式块、重排偏移，长度不限）；
* 可以**留空**（保持日文）；
* 可以增删标点、合并/拆分句子（在**一行之内**）。

**不允许的**：

* 改 `id` / 增删行 / 改列结构；
* 在同一行里加**换行符**（TSV 单元内不能有真实换行）；
* 改脚本结构（增删命令）——本工具链只做文本替换。

## 2. 名牌、前缀与「文字里的语法字符」

这一节是**最容易把游戏改崩**的部分。核心认知：

> **游戏里的"正文"不只是给人读的文本，它同时是引擎的输入。**
> 有 4 类字符引擎会**当语法解析**：ruby 定界符、控制字节、名牌分隔符、以及标点微调字符。

### 2.1 说话人前缀＝引擎语法

说话人名字**不在单独的字段里**，就在正文开头：

```
カノ「おはよう……」        ← 普通台词
珠夜『そうか……』          ← 内心话 / 复述
文鳴（なぜだろう）          ← 心声
```

引擎运行时（`eris\es_charname.yst` 的 `#es.CHAR.NAME.SEARCH`）拿这一行的**前缀**去比对注册表 `userdefine\キャラ名定義.txt` 里注册的名字（参考作品：74 个注册项、63 个唯一名），并要求名字后面**紧跟一个注册过的标记**（参考作品注册了 3 个：`「` `『` `（`）。

* **命中** → 前缀被整段切掉，名字画到**名牌**上，正文只剩标记后面的内容。
* **没命中** → 不切，整串 `名字「正文」` 全画进正文，**名牌是空的**。

所以：

> **规则：`名字 + 标记` 这一段照抄日文原名和原文那个标记，只翻译标记后面的内容。**

例：

| 原文 | 建议译文 |
| --- | --- |
| `カノ「おはよう……」` | `カノ「早上好……」` |
| `文鳴（なぜだろう）` | `文鳴（到底为什么）` |

注意**收尾标记要跟着开头标记走**：`「」`/`『』`/`（）` 三对别混。已经误改的前缀可以用 `fix_name_plates.py` 机械修回（默认 dry run，`--apply` 才写盘，会留 `.bak`）。

### 2.2 名牌要不要翻成中文

| 方案 | 代价 |
| --- | --- |
| **保留日文原名（默认，零风险）** | 名牌上是日文名，但和人物一一对应，玩家接受度高 |
| 改中文名 | 需要**额外翻译** `キャラ名定義.txt` 并往编译脚本里**新增 `GOSUB` 记录** ⇒ **本工具链做不到**（注入只做等长替换）。若坚持要做，得先扩展注入器支持"新增命令"，或者改引擎 |

还有一个**隐形约束**：改名以后，**全游戏的说话风格/称呼**必须和你的术语表一致，否则同一个角色在两处叫不同名字，玩家会以为是两个人。

### 2.3 ruby（注音）

原文写法：`≪` 起点、`／` 分隔、`≫` 终点（`≪`/`≫` 在 CP936 里没有码位，构建时自动替换成 `《`/`》`）。

| 类型 | 形状 | 例 | 含义 |
| --- | --- | --- | --- |
| **读音注** | `≪汉字／假名≫` | `≪剃刀／かみそり≫` | 作者标注的读法 |
| **强调注** | `≪一字／・≫` | `≪そ／・≫≪れ／・≫` | 逐字加着重号，**每段恰好一个字**，读音位置写 `・` |

参考作品统计：16 308 行里 **1 592 行**含 ruby，其中 206 行是强调注；单行最多 16 段（引擎上限 **64** 段，超了报 `ルビ指定が多すぎます`）。

**处理规则**：

1. **读音注 → 全删**，只留中文正文。理由：中文不需要假名注音，ruby 字号很小（参考作品 7 px）只会变成噪点。
2. **强调注（`／・`）→ 保留**，段数尽量和原文一致（它承载"强调"这个表演信息）。删掉也可以，但**不要凭空新增**（行检器会对"比原文多"报警告）。
3. 懒得动 ruby 就**整段照抄原文**的 ruby 片段，也是安全的。
4. **不要自己写 `≪` `／` `≫`**（除非刻意复刻强调注）。中文的间隔点直接用 `·`。

### 2.4 `《》《》` 是引擎语法，书名号用 `〈〉`

这是**唯一一条写错当场崩游戏**的排版规则：

* 构建时替换表把 `≪`→`《`、`≫`→`》`，这份替换表**同时作用在引擎脚本上**——所以引擎那边的 ruby 定界符定义也变成了 `《` `／` `》`，解析器**真的会去解析你译文里的 `《…》`**。
* 解析器是逐字符**三态机** `正文 -《- 基字 -／- 读音 -》- 正文`，任何偏离都弹
  `[エラー] …行目 ルビ記述エラーです。`，**OK 之后结束游戏**。

具体触发条件（完整表见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) §2）：

* `《…》` 里**没有 `／`** → 报错（当成读音为空的 ruby）；
* 行尾还有未闭合的 `《…` → 报错；
* `《` 后面直接跟 `／`（基字为空）→ 报错；
* 嵌套 `《`、单独一个 `》` → 报错；
* **单独一个 `《`（不配对）→ 不报错，但静默从显示里删掉**（隐形丢字！）。

**处置**：

* 书名、作品名、章节名 → **`〈` `〉`**（U+3008/U+3009，CP936 里存在，引擎不认作分隔符）；
* 一般引号 → `「」`（引擎对 `「` 有标点微调，显示正常）或 `“”`；
* 只有注音才用 `《基字／读音》`，且必须成对。

### 2.5 禁用 4 个汉字：`镳` `锺` `矧` `矬`

这 4 个字的 GBK 字节是 `EF F0`/`EF F1`/`EF F2`/`EF F3`，**引擎把它们当控制码**：

| 汉字 | 引擎动作 |
| --- | --- |
| **镳** | 删除该字 + 写一条空日志项 |
| 锺 | 未处理，正常显示（但字节对是保留的，别用） |
| **矧** | 删除该字 + **强制翻页** |
| **矬** | 删除该字 + **停下等点击** |

`EF` 开头的 GBK 汉字一共 190 个，只有这 4 个形成完整字节对——**是精确的 4 个，不是一类**。

实测受害词：`分道扬镳`。这 4 个字没有等价写法，**只能整个换掉这个词**。

### 2.6 构建时的自动替换（别依赖它，但要知道）

有 4 个字符在 CP936 里没有码位，工具会自动换成等长的 2 字节字符：

| 原字符 | 替换为 |
| --- | --- |
| `≪` | `《` |
| `≫` | `》` |
| `・` | `·` |
| `♪` | `。` |

**译者应该主动写对**：`・` 直接写 `·`；`♪`（歌词/哼唱）自己挑合适的中文（`～`、`～♪` 不行就用 `……`），别让工具把它变成句号。

## 3. 术语一致性（模板）

本仓库**不带**术语表。请自建 `glossary/glossary.tsv`（模板已给出表头与格式说明）：

```powershell
# 从原文里挖候选术语（按出现次数排序）
python extract_terms.py --workpack workpack --outdir glossary

# 用你自己的术语表检查译文一致性
python check_glossary.py --glossary glossary\glossary.tsv --lines workpack\lines.tsv
```

要点：

* **人名/地名先定，再动手**。参考作品有 20+ 个专有名词（人、岛、组织），定名越晚，返工越多。
* 术语表里**每行一条**，写「原文 → 译名 → 备注（可否变体）」。
* 行检器会检查：同一条原文是否被译成不同写法、术语是否被漏用。警告不代表错，但**每条都值得看一眼**。
* 人名在**名牌**（§2.1）和**正文称呼**里必须一致，否则玩家会以为换了人。

## 4. 其他写作约定

| 项 | 约定 |
| --- | --- |
| 标点 | 用**全角**中文标点（`，。？！：；`），不要用半角 |
| 省略号 | `……`（两个 U+2026），不要用 `...` 或六个点 |
| 破折号 | `——`（两个 U+2014） |
| 间隔点 | `·`（U+00B7），不要写 `・` |
| 数字 | 与原文保持一致（原文用汉字就用汉字，原文用半角数字就用半角） |
| 引号 | 台词用 `「」`；书名用 `〈〉`；**不要**用 `《》` |
| 语气/口癖 | 方言、口癖（关西腔、古文腔）用**中文的语体**体现，不要用注音或括号解释 |
| 拟声词 | 参考作品里很多拟声词单独成行，可保留原文或换中文拟声，**但同一词要统一** |
| 不要做的事 | 不要加译注（游戏里没有地方放）、不要在行内加换行符、不要加 emoji（CP936 编不出来） |

## 5. 宽度预算

引擎按**像素宽度**排版，超宽就**自动分页**（不截断，但会多一页），所以"能放下多少字"是可以算的：

```
每字前进量 = 文本定义的格宽 + 字距
可排版宽度 = 文本框宽度 - 左右边距
每行字数   = 可排版宽度 / 每字前进量
```

参考作品实测值（**换游戏/换字号必须重算**）：

| 量 | 值 |
| --- | --- |
| 对白定义 `M` 的格宽（`PINT`） | 30 px |
| 全局字距（`@gInt1144(36,19)`） | −2 px |
| 每字前进量 | **28 px** |
| 可排版宽度 | ≈ 790 − 40 = **750 px** |
| **每行全角字数** | **≈ 26** |
| 每屏行数 | 5 |

**结论：一行翻译**最好**控制在 26 个全角字符以内**。

实际统计（参考作品 10 195 行）：译文字节长度比原文的中位数 0.74×、p95 1.00×、最长 2.50×，只有 **22 行（0.2%）**超过 1.25×——说明**中文通常比日文短**，长度基本不是问题，需要留意的是那些**原文很短、译文无法压缩**的地方（双关、专有名词全称等）。

压缩手段（优先级从高到低）：

1. **改句子**：中文压缩余地通常在虚词和重复称谓上；
2. **调字距/字号**：`python tune_dialogue.py --char-space -4` 或 `--size "M=28x30"`——这是**全局**调整，会影响所有行；
3. **不要指望引擎缩字**：`lfWidth` 恒为 0，字形不会被压扁。

行检器会给出**宽度警告**（默认阈值 `--width-ratio 1.25`），只对超出的行报警，数量不多，值得逐条看。

## 6. 提交前自检清单

```powershell
# 1. 行级检查（术语一致性、前缀、ruby、宽度、禁用字）
python check_glossary.py --lines workpack\lines.tsv

# 2. ruby 语法回归（18 个用例）
python test_ruby_check.py

# 3. 控制字节回归
python test_control_check.py

# 4. 构建（内部会自动跑全部 8 项验收检查）
python build_cn_pack.py --workpack workpack --indir D:\ysbin --out build --install --install-dir "<游戏目录>"
```

必须全部 `ok` / `PASS` 才算完成。构建日志里要确认这几行：

```
N script(s) re-encoded, M unchanged, 0 skipped
[N] the X dialogue line(s) holding a ruby delimiter parse ok
[N] 0 engine control character(s) in the drawn text ok
PASS: build\update1.ypf is safe to install
```

`verify_cn_pack.py` 八项检查的具体含义与 FAIL 处置见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) §7。

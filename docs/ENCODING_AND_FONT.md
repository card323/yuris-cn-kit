# 编码与字体（ENCODING_AND_FONT）

这一页回答三件事：**为什么必须是 GBK**、**字体是怎么被游戏选中的**、**换字体/换字号到底在改什么**。

---

## 1. 编码、字符集、代码页：三个别混起来的东西

| 概念 | 是什么 | 在本项目的实例 |
| --- | --- | --- |
| **字符集 / 字形覆盖** | "有哪些字、长什么样" | 日文字体里**没有**简体字的字形；中文字体里有 |
| **编码（encoding）** | "一个字符用哪些字节表示" | CP932（Windows Shift-JIS）、CP936（GBK）、UTF-8 |
| **代码页（code page）** | Windows 给编码起的编号，也是 API 的解码依据 | 932 = CP932、936 = CP936、65001 = UTF-8 |
| **字符集字段（`lfCharSet`）** | `LOGFONTA` 里告诉 GDI"用哪个代码页解这串字节" | 补丁把它从 0（ANSI＝跟系统）改成 `0x86`（GB2312→CP936） |

**为什么不能改成 UTF-8。** 引擎是**按字节走**的 DBCS 引擎：它有一个 256 字节的"前导字节表"决定每个字符占 1 还是 2 字节（[ENGINE_NOTES.md](ENGINE_NOTES.md) §6.1），所有字符串长度、偏移、换行宽度、字距算法都按**字节数**和**字宽**算。UTF-8 是 1–4 字节的可变长编码，一个汉字 3 字节，这个假设直接崩掉；而且 GDI 的 ANSI 路径（`TextOutA` + `lfCharSet`）根本没有"按 UTF-8 解码"这个选项。

**能用的只有双字节字符集（DBCS）**，而且必须满足：

1. 常用字都是 **2 字节**（和 CP932 的网格一致，换行/宽度公式不用改）；
2. 前导字节范围能用**一张连续的 256 字节表**表达（这样 exe 里那个表只需换内容，不用改代码）。

CP936（GBK）两条都满足：常用汉字 2 字节、前导字节 `0x81–0xFE` 连续无空洞。Big5（繁中）也满足，但目标是简中；CP932 做不到——它**装不下**简体字（很多简体字在 CP932 里没有编码，日文字体里也没有字形）。

> **注意**：名字里"GBK = 扩展 GB2312"这个关系只在覆盖面层面成立。工具链里 `gbk` / `cp936` / `936` / `ms936` 是**同一个代码页的别名**（`transcode_yuris_scripts.py` 的 `CP936_ALIASES`），代码页号 936。

## 2. 为什么引擎脚本必须"等长转码"

对白走的是"注入"：把字符串切出来、替换内容、重排偏移（长度随便变）。
**引擎脚本（索引 0–181）走的是"原位转码"**：不解包结构、不重排任何东西，只把每个字符串字面量**原地换成同样长度的字节**。

能这么做，靠的是这条算术：

```
ASCII（0x00–0x7F）     CP932: 1 字节    GBK: 1 字节     ✓ 等长
假名 / 汉字 / 全角符号  CP932: 2 字节    GBK: 2 字节     ✓ 等长
4 个无法映射的字符      见 §3.4：替换成的字符也是 2 字节   ✓ 等长
```

于是长度守恒 ⇒ **偏移、长度字段、命令块、参数块、行号块、分支目标统统不用动**，改完的文件和原文件**大小完全一样**。`transcode_script()` 每次写完都会回读验证（命令块/行号块/参数块逐字节相同），不通过就拒绝写盘。

**字体名是唯一例外**：它要**改名**（不是转码），因为 `ＭＳ ゴシック` 的 GBK 字节序列匹配不到任何字体。改名也要求等长——那个字面量是**固定 13 字节**的槽位，所以新名字必须 **≤ 12 字节 + NUL**（`Glow Sans SC` 正好 12 字节）。带参数 `--face` 时工具会强制检查长度，超了就报错。

**字号/字距/行距也是"改一个字节的立即数"**，所以同样不动任何偏移：`--td-size`、`--char-space`、`--line-space` 都属于这一类。

## 3. 选择 CP936 的理由（以及它的代价）

| 理由 | 说明 |
| --- | --- |
| 目标语言 | 简体中文，CP936 是 Windows 上的标准代码页 |
| 网格兼容 | 2 字节汉字与 CP932 的"一个汉字一个格"一致，字宽/换行/字距算法全部复用 |
| 前导字节连续 | `0x81–0xFE` 全体前导 → exe 里那张表只需按 `IsDBCSLeadByteEx(936, b)` 重写 |
| 系统字体齐全 | 所有中文 Windows 都自带可渲染 CP936 的字体；GDI 的 ANSI 路径只需要 `lfCharSet` |
| 覆盖面 | 简繁汉字、假名、全角标点、常用符号都在 |

代价（都已被工具链处理）：

* **4 个字符没有映射 / 不能用** → §3.4；
* **4 个汉字撞上引擎控制字节**（`镳` `锺` `矧` `矬`）→ [ENGINE_NOTES.md](ENGINE_NOTES.md) §6.4；
* **`ysl.ybn` 等表里的标识符仍是 CP932**，所以路径/label 名一个字都不能改 → [ENGINE_NOTES.md](ENGINE_NOTES.md) §7。

### 3.4 无法映射的字符与自动替换

引擎脚本里有 4 个字符在 CP936 里没有对应编码，工具链用**等长的 2 字节字符**替换（`transcode_yuris_gbk.py::SUBSTITUTIONS`）：

| 原字符 | 替换为 | 说明 |
| --- | --- | --- |
| `≪` (U+226A) | `《` | 引擎的 ruby 定界符；CP936 里没有 `≪` |
| `≫` (U+226B) | `》` | 同上 |
| `・` (U+30FB) | `·` (U+00B7) | 中点；GBK 里 `・` 不保证存在 |
| `♪` (U+266A) | `。` | 音符；GBK 里没有 |

**这四组替换是工具自动做的，译者不要手写**——脚本里出现 `≪` `≫` 时说明那是 ruby 语法（见 [TRANSLATION_RULES.md](TRANSLATION_RULES.md) §2），而 `・` `♪` 出现在对白里时应该由译者自己挑更好的中文写法，不要依赖自动替换。

如果某个字**根本没法用 GBK 表示**（例如 emoji、生僻的 CJK 扩展字），`transcode_yuris_gbk.py` 会**拒绝整行并报 FATAL**，而不是悄悄丢字。这就是"译文只能用 CP936 里有的字"这条约束的执行点。

## 4. 字体：游戏到底在用哪一个

引擎有**两条独立的字体路径**，改汉化时两条都要管：

| | 路径 A：exe 默认面表 | 路径 B：脚本文面量 |
| --- | --- | --- |
| 谁指定 | exe 的 `_RDATA` 面名表（3 个槽，**取第一个系统里存在的**） | 引擎脚本里的 `ＭＳ ゴシック` 字面量，由 `TD.FONT.SET` / `FONT[NAME=…]` 使用 |
| 覆盖范围 | 脚本没显式指定的部分（部分菜单、系统消息等） | **对白、选项、N 名牌**（`M` / `NAME` / `M_TATE` 定义） |
| 有兜底链吗 | **有**（3 个槽依次尝试） | **没有**：GDI 找不到就静默替换 |
| 改法 | `patch_yuris_charset.py --fonts "…"`（改 exe，16 字节/槽） | `transcode_yuris_scripts.py --face "…"`（改脚本，为 **13 字节固定槽**） |
| 长度限制 | 名字 + NUL ≤ 16 字节 | 名字 + NUL ≤ 13 字节（即 ≤ 12 字节） |

两条路径的名字都交给 **`CreateFontA`**，也就是用**进程 ANSI 代码页（这里是 932）**解码，所以：

* 必须写**字体注册的 ASCII 名**（`SimSun`、`MS Gothic`、`Glow Sans SC`），不要写本地化名（`宋体`、`ＭＳ ゴシック`）；
* 名字里的字节一旦解码失败，GDI 就换一个字体，你看到的观感和你想的不一样。

### 4.1 名字对不上就一定会被静默替换

GDI 只看字体的 **name ID 1（Family）**，完全忽略 name ID 16（Typographic Family）。而 Glow Sans 官方发布版注册的家族名是 `Glow Sans SC Normal Medium`（19–24 字节）这种，"Glow Sans SC" 只存在于 ID 16 —— 所以**直接写 `Glow Sans SC` 会被静默换成 SimSun**。这就是 `install_glow_sans.py` 存在的原因：它改写字体的 name 表，把两个字重注册成

```
Glow Sans SC        ← GlowSansSC-Normal-Light.otf      （400 槽，对白）
Glow Sans SC Bold   ← GlowSansSC-Normal-<bold>.otf     （700 槽）
```

**这是"改字体文件"，不是"改游戏"**，而且是**按用户安装**的（`%LOCALAPPDATA%\Microsoft\Windows\Fonts` + `HKCU` 注册表项），不碰系统字体目录，`--uninstall` 能精确撤销。

### 4.2 字重：为什么调了半天"还是太粗"

* 引擎的字体构造器**只请求两个 `lfWeight`：400 和 700**，没有第三档。你给什么字重，它只是"就近取"。
* 渲染是 **1 bpp 位图**（`CreateFontA` + 单色 DIB），**没有抗锯齿**。同一个字重在 1bpp 下的笔画看起来比屏幕上（灰度平滑）**粗一档**——这是"明明选了 Regular 还是粗"的根本原因。
* 所以字重是**唯一的粗细旋钮**：想更细只能往更细的字重走（这就是最终落在 **Light 300**、两个槽都用的原因），再想细就只能动字号。
* **Glow Sans 的命名陷阱**：`Book` 是 **500**，比 `Regular`（400）**更粗**。想细就往 `Light`/`ExtraLight` 走，别被名字骗了。

### 4.3 系统里没有这个字体时会发生什么

| 场景 | 结果 |
| --- | --- |
| 路径 A（exe 表）里有名字存在 | 用那个 |
| 路径 A 三个名字都没有 | GDI 兜底到系统默认（观感变，不崩） |
| 路径 B（脚本字面量）名字不存在 | **静默替换**（实测落在 SimSun）：对白**照常显示**，但字形/字宽/空白全变——因为新的字宽与 `--td-size`/`--char-space` 的假设不再匹配，看起来偏小、偏挤或偏散 |
| 玩家在游戏里改过字体 | `save\config.sd` 里的选择**优先于**上面两条（见 §6） |

**发布补丁时的选择**（三种，按推荐度）：

1. **补丁器自带 OTF 并安装**（`install_glow_sans.py` 那套逻辑）：用户装完即得预期观感。OFL 允许这样分发，但要把 OFL 文本和版权声明一起给（见 [NOTICE.md](../NOTICE.md) §3）。
2. **打包时用一个"人人都有"的字体名**（`Microsoft YaHei` / `SimHei` / `SimSun`，≤12 字节，都在 pre-9x/9x Windows 里自带）：零依赖，代价是观感和字宽要重算（`--td-size` / `--char-space` 得跟着调）。
3. **只在说明里要求用户自己装 Glow Sans**：最省事，但用户不装就落到 §4.3 的静默替换。

> ⚠️ **请务必二选一写清楚**：包里的面名和用户机器上的字体必须对得上，否则你看到的排版是你的机器"恰好装了字体"的结果，别人看到的是另一套。

### 4.4 字体名在**包里**，不在字体里

`update1.ypf` 里**没有**字体文件，只有**字体名**（脚本字面量那一串字节）。所以：

* 想换字体 = **重新打包**（改字面量 → 重建 `update1.ypf`），不是"换个 OTF 就行"；
* 反过来，只要名字不变，字体文件本身随便你换（`install_glow_sans.py --weight` 换字重就是这一招，**不用重新打包**）；
* "补丁是否依赖 Glow Sans" 的答案：**依赖它的名字**。名字在包里，字体在系统里——名字对不上就落到 §4.3。

### 4.5 为什么最后选 Glow Sans

* **覆盖**：本作译文用到的 4 481 个不同字符，Glow Sans SC **一个都不缺**；换成 `ＭＳ ゴシック` 则有 **880 个**字符没有字形（日文字体没有简体字形）。
* **观感**：字面比 `ＭＳ ゴシック` 略窄、字重可选范围大，1bpp 下 Light 更接近原作的笔画感。
* **许可**：SIL Open Font License 1.1，**未声明 Reserved Font Name**，所以允许改名、允许随补丁分发（条件是：附 OFL 文本与 `Copyright (c) 2020, Celestial Phineas`、不能单独售卖字体本身、派生物必须继续用 OFL 且不得用原作者名义背书）。完整条件见 [NOTICE.md](../NOTICE.md) §3。

## 5. 字号 / 字距 / 行距：三个旋钮的确切含义

文本定义由 `userdefine\文字定義.txt` 里的 `es.TD.SIZE.SET` 建立，随后 `es.TDDEF.SET` 把它"提交"成名字（`M` = ADV 对白框、`NAME` = 说话人名牌、`M_TATE` = 竖排）。两个操作数不是一回事：

| 参数 | 含义 | 效果 |
| --- | --- | --- |
| `PINT` | **格宽**（笔每次前进多少像素） | 决定每行能放几个字、字与字的间距 |
| `PINT2` | **字形高度** | 决定字画出来多大（`lfHeight=PINT2`、`lfWidth=0`，字形保持自然比例） |

`--td-size "M=30x32"` 就是 `PINT=30`、`PINT2=32`。**非方形格子是刻意的**：Glow Sans 的字面比它的前进量窄（0.812 em vs 0.852 em），所以用"**高一点、窄一点**"的格子（30×32）让字保持该有的大小、同时把字间空隙收掉。`NAME=30x32` 同理把名牌也放大。

字距/行距不是文本定义的属性，而是渲染器加的两个**全局像素常量**（`es_text.yst` 里 `cell width + @gInt1144(36,19)`、`glyph height + @gInt1144(36,20)`）：

| 参数 | 字段 | 本作发布值 | 说明 |
| --- | --- | --- | --- |
| `--char-space` | `@gInt1144(36,19)` | **-2**（游戏原值） | 负值收紧字距；宽字面字体需要它 |
| `--line-space` | `@gInt1144(36,20)` | **0** | 行距 |

**行宽预算怎么算**：（把这两项相加/相乘前先记住：一次只动 `M` 和 `NAME`，菜单不动）

```
每字前进量 = 格宽 + 字距 = 30 + (-2) = 28 px
可排版宽度 ≈ 790 - 40（左右边距） = 750 px
每行全角字数 = 750 / 28 ≈ 26 个
一屏 5 行，超出行宽的部分由引擎自动分页（不截断，但会多一页）
```

这就是 [TRANSLATION_RULES.md](TRANSLATION_RULES.md) §5 那条"约 26 个全角字符/行"的出处。改 `--td-size` 或 `--char-space` 之后，这个数字要**重新算**。

### 5.1 一处**换字体时最容易漏掉**的坑：行高单位

引擎请求 `lfHeight = PINT2`，但**行距由脚本固定**，而 GDI 把 `lfHeight` 按**字体自己的 ascent+descent** 缩放。所以"字号"能不能兑现，取决于字体的行度量是不是 **1 em**：

| 字体 | hhea/win 度量 | 结果 |
| --- | --- | --- |
| `ＭＳ ゴシック` | 220/-36（÷256 = **正好 1 em**） | `PINT2` 就是实际字形高度 |
| Glow Sans SC 发布值 | 1160/-288 = **1.448 em** | 同样的 `PINT2` 只画出**约 2/3** 的大小 → 字小、行距看着变宽 |
| Glow Sans SC（`--line-metrics typo`，880/-120 = 1 em） | **1 em** | 与 `ＭＳ ゴシック` 同一约定，字号才说了算 |

`install_glow_sans.py --line-metrics typo` 就是改这个（把 `hhea`/`win` 度量改成 OS/2 typographic 那一组）。**换任何字体都要先确认这一条**，否则你会一直觉得"字号调不上去"。

### 5.2 一键调参

```powershell
python tune_dialogue.py --size "M=30x32, NAME=30x32" --weight light --bold-weight light
python tune_dialogue.py --char-space -4            # 更紧
python tune_dialogue.py --preview-sizes "24,26,28,30" --text "测试一行对白" --lang cn --zoom 2
```

`tune_dialogue.py` 会按需安装字体（`[font]`）→ 重新打包（`[build]`）→ 生成预览图（`[look]`），并把当前设置记在 `build\tune_state.json` 里；**只有字重/行度量变化才需要重装字体**，只改字号/字距时不会碰字体文件。

## 6. `save\config.sd`：会让你的调整"看起来没生效"

玩家在游戏里改过的设置存在**安装目录的 `save\config.sd`** 里，其中包括**字体选择**（設定 → フォント一覧）。它的优先级**高于** exe 面名表和脚本文面量。

所以：**改完字体以后，如果游戏以前跑过，就把 `save\config.sd` 改名或删掉**（先备份，例如 `config.sd.prefont.bak`），否则你看到的还是旧字体。副作用：音量、文字速度等设置会回到默认。

同样的坑还有一个变体：**游戏在跑的时候改包不会生效**（它启动时把包读进内存），改完必须重启游戏。
